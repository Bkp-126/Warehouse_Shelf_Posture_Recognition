# 技术讲解与作品集叙事

## 这次迭代解决什么问题

旧界面按整幅画面从“没有动作”切换成“有动作”计数。一人持续伸手时，第二个人伸手不会单独计数；关键点短暂漏检后重新出现又可能多算。这次把统计单元改成“会话内人物轨迹 + 动作 + 区域”，并把单帧判断转换成带开始、结束和有效时长的事件。

自己的贡献是应用流程、姿态规则、事件机制、证据与复核链路，以及能定位错误的验证；关键点网络和跟踪器来自第三方。不能把调用现成网络包装成自研人体姿态模型。

## 状态机怎么解释

候选要连续满足0.3秒才建立事件；进入和退出用不同角度，避免在边界来回闪烁。已建立事件可容忍0.2秒缺点，但这段时间不增加有效姿态时长。长时间缺点就截断，不假定人在遮挡后一直弯腰。恢复正常持续0.5秒后结束事件，结束时刻回到最后一次正向观察。

10秒提醒每个事件只发一次。用户停止、视频结束或解码失败时，也记录事件为何结束。所有时间来自视频，与GPU快慢无关。

## 为什么没有直接换新模型

更好的关节点不能修复错误坐标、重复文件名、多人合并或视频循环统计。四组对照把画面级旧规则、逐人规则、时序规则和新骨干分开。输出事件更少并不一定更准，也可能漏掉动作；正式解释必须依赖独立人工标签。

## 具体失败边界

- 肩髋膝的二维角度可能把蹲下、坐下或转身当弯腰候选。没有三维标定，不输出健康风险评分。
- 人太远、被货架遮住或两人重叠时，关键点和跟踪身份可能断裂。跟踪编号只在当前会话有效，不能用于识别人。
- 手腕在图像区域内不等于拿到了物品；本版不识别抓取成功。
- 弯腰与伸手可以同时发生，分别记事件，不能把总数当不同动作次数简单相加。
- 不确定区间会减少可统计时长。报告无法判断覆盖，避免只展示“有把握”的片段造成误解。
- 本次短示例没有真实持续10秒弯腰提醒样例。合成序列验证了软件边界，不能据此声称现场提醒能力已经验证。

## 面试时可以演示

展示原始缺陷 → 打开视频设置区域 → 查看逐人事件 → 回放证据 → 说明开发／固定回归隔离 → 展示测试和真实视频输出 → 展示一个失败与待核验项目。

演示视频由已保存的预测生成，明确标注为流程回放，没有伪造手工操作或准确率。真实GUI/GPU工作线程验证记录另存，二者不要混淆。

历史YOLO11s微调训练、旧ONNX和TensorRT资产保留在归档，只作为历史实验。当前发布基线使用YOLO11n-pose；不把历史训练结果和当前事件系统拼成不存在的统一成绩。
